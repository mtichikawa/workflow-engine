How it works

Small parts, checked and gated

A shared library

15 single-job specialists (classify, verify, match, extract, act…), one instance each, configured per workflow. A new job mostly reuses what's on the shelf.

Checked before it runs

A static validator follows every wire and condition: a step must read something that exists and has already run, and anything that acts outside the engine must sit behind a human gate.

Learns per workflow

Each workflow keeps its own corrections. From 8 on, it writes a rulebook from them; each call also sees the 6 most similar. Nothing crosses between workflows.

The honest frame. The components aren't novel: orchestration, few-shot retrieval and human-in-the-loop review all exist. What's here is a working synthesis built from scratch, with measured results, and every decision defensible end to end.

      Run it yourself · about 60 seconds
      git clone https://github.com/mtichikawa/workflow-engine && cd workflow-engine
python3 -m venv .venv && source .venv/bin/activate
pip install -e '.[live]'
python -m engine.cli compose "sort support emails by type and draft a reply"
python evals/blind.py validator      # re-run a sealed evaluation
      Bugs its own tests found

      A step reached by both a "pass" and a "fail" edge was always skipped, so the triage recipe's approval step never ran. A seeded-fault test found it on 2026-10-14; it's fixed and covered by a regression test.
