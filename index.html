A from-scratch AI workflow engine

Describe a task in plain English. Get an AI workflow you can check.

  • Builds the workflow from small, single-job AI specialists
  • Refuses to run a plan that's wired wrong
  • Stops for a person before anything leaves it
  • Learns a team's unwritten rules from their corrections

Every number below comes from a test set written separately from the engine, and can be re-run.

One engine, several workflows

  • A shared library of single-job specialists does the general work: sort, score, match, check, act.
  • A workflow adds its own specialists only where the work is specific, like reading a fax or a health plan's billing rules.

Each column is a workflow with a recorded run. See them run.

How it works

A shared library

15 single-job specialists for general judgments: sort, match, check, extract, act. A workflow configures them, never copies them. Domain work is new code: the healthcare demo uses from the library and written for it (reading scans, plan rules, the claim).

Checked before it runs

Every wire must lead to something that exists and has already run. Any step that acts outside the engine must sit behind a human gate.

Model where judgment is needed, code where it isn't

Reading a scan or a message: the model. Plan rules, the claim form and the safety sentence: plain code, the same every time.

How it learns

No fine-tuning. Each workflow keeps its own corrections, and nothing crosses between workflows or customers.

1 · Instructions

What the step is for: its categories, criteria, any written policy. With no corrections, that's all it has.

2 · A rulebook it writes

From 8 corrections on, it writes down the rules they imply, and rewrites them as corrections come in.

3 · The closest examples

Each call also sees the 6 past corrections most like the input, so the rules come with cases.

On a clinic's messages it went from 59.3% → 97.3% as staff corrections accumulated, with no fine-tuning. Watch it learn

The workbench

One page to make, keep, run and correct workflows: python -m engine.app

  • Describe a task; the composer drafts it; adjust the steps in a form
  • Every save is a new version
  • Runs take pasted text, a CSV, a folder, a webhook, or a folder on a schedule

What it can't do yet

  • No real sending: no email, no claims portal, no eligibility check with a payer.
  • No general image reader: scans are read only in the healthcare demo.
  • One machine, no login.
  • Learning beats a long prompt on size, not accuracy, at a few hundred corrections.
  • Tests and engine both use Claude, so they may share blind spots. All test data is synthetic; no person has checked the labels.

Tested

Every number on this site comes from a test set written separately from the engine. How:

  1. A separate Claude agent, with no access to the code, wrote the test set.
  2. A second one labelled it again; only items both agreed on were kept.
  3. Sealed with a hash before the first score; scored once.
  4. A change to the engine gets a new set, never a re-score.
  5. Every result has its sample size, a baseline and a 95% interval.

Method and raw results: docs/blind-evals.md · evals/blind-results

        More measurements

        Smaller or less independent than the four above, so they aren't headlines.

        Bugs its own tests found (5)
        • A step reached by both a "pass" and a "fail" edge was always skipped, so the triage workflow's approval step never ran. Found by a seeded-fault test; fixed, with a regression test.
        • The validator crashed on an edge to a step that doesn't exist. Fixed.
        • The new validator caught the composer's own mistake: in the demo, its draft wired a list into a field that takes text. The composer now repairs it before running.
        • An approval step that came after the action. Driving the workbench in a browser showed a gated file step writing its file first and asking second; a rejected item had already written. Outside actions now wait for approval before they run.
        • Every item wrote the same file, and a saved workflow's corrections went into the shared example set. Staged files are never overwritten now, and each workflow learns in its own folder.

          3 · What the person reviews at the gate

          What a healthcare team would ask

          Design facts, not compliance claims.

          Medical content goes to a person

          A written policy decides what's medical, mental-health warning signs included. The assistant never answers it; a nurse is alerted.

          Replies stay inside the line

          Replies cover coverage and scheduling only. The safety sentence is fixed text; a second model checks every draft.

          A record of every decision

          The packet a person approves holds the claim, the reply, the nurse handoff, the open items, and where every field came from.

          Model calls go to Anthropic's Claude; documents and results stay on the machine running the engine. It has not been tested on real patients or real payer systems.
